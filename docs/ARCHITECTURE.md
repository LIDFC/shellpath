# Как устроен код

Игра целиком работает в браузере: настоящих серверов нет, всё — модель в памяти. Логика не знает про DOM, поэтому её можно запускать и тестировать в Node.

```
index.html            разметка страницы
styles/main.css       стили (токены описаны в docs/DESIGN.md)
src/
  main.js             точка входа в браузере
  i18n/ru.js          все русские строки интерфейса, подсказок и справок man
  core/
    state.js          состояние игры (S), блоки, сохранение прогресса
    fs.js             виртуальная файловая система: узлы, права, пути
    io.js             связь логики с интерфейсом: print, ask, IO
    shell.js          разбор строки, конвейеры, перенаправления, дополнение по Tab
    session.js        вход на уровень, вложенные SSH-сессии, exit
    rng.js            детерминированный генератор (пароли одинаковы у всех)
  commands/           команды; каждая регистрируется через register()
    basic.js          ls, cat, find, grep, sort, …
    files.js          touch, mkdir, chmod, rm, cp, mv, nano
    keys.js           модель SSH-ключей
    ssh.js            ssh, ssh-keygen, ssh-copy-id, sshd -t
    net.js            ip, ping, traceroute, sysctl, iptables, systemctl, …
  netsim/             модель сети для блока «Сеть»
    ip.js             арифметика IPv4
    iptables.js       таблицы filter и nat
    lab.js            машины, etcnet, путь пакета, NAT, GRE, DNS
  worlds/             данные миров
    base.js           сервер shellpath, пароли
    ssh-world.js      хосты блока SSH: порты, кого пускают
    lab-world.js      топология лаборатории
  levels/             уровни — данные + эталонные решения
    basic.js, net.js, ssh.js, index.js
  ui/
    app.js            терминал, патч-панель, задание, nano, прогресс
    markdown.js       безопасный мини-Markdown для текстов уровней
scripts/
  serve.mjs           локальный сервер без зависимостей
  bundle.mjs          склейка модулей в один скрипт
  build.mjs           сборка dist/shellpath.html
tests/                node:test, без зависимостей
```

## Как выполняется команда

1. Игрок нажимает Enter. `ui/app.js` вызывает `runLine(строка)` из `core/shell.js`.
2. `tokenize` разбирает кавычки, `$VAR`, `~`, перенаправления; `parse` собирает конвейеры и `;`, `&&`, `||`.
3. `runPipe` раскрывает `*`, находит команду в реестре `C` и вызывает её с `{ stdin, tty }`.
4. Команда возвращает `{ out, err, note, code }`. `out` идёт в следующую команду конвейера или на экран, `note` — наша подсказка по-русски.
5. Долгие команды (`ssh`, `ssh-keygen`, `nano`, `labcheck`) асинхронные: они сами печатают через `print` и задают вопросы через `ask`.

## Дополнение по Tab

`complete()` в `core/shell.js` смотрит, какое слово дополняется. Первое слово — имя команды. Дальше, если у команды есть правило в `COMPLETERS` (`commands/registry.js`), варианты берутся из него: так дополняются `ip link set ens18 up`, `systemctl restart network`, `iptables -t nat -A POSTROUTING -j MASQUERADE`, ключи `sysctl`, хосты для `ssh`. Если правила нет или оно вернуло `null`, дополняются имена файлов.

Чтобы Tab не решал уровни «Начального» блока, имена файлов по пустому слову не подставляются (только список), а без кавычек дополнение останавливается перед пробелом.

## Файловая система

Узел — `{ t: 'd' | 'f', o: владелец, g: группа, m: права, c: дети | d: содержимое }`. `FS.root` — корень текущей машины: у основного мира одна ФС на все SSH-хосты, у каждой машины лаборатории — своя. `lookup` проверяет право входа в каталоги по пути, `can` — права rwx текущего пользователя.

## Сеть

`netsim/lab.js` держит машины лаборатории в `LAB.hosts`. У машины есть ФС (с `/etc/net/ifaces`) и состояние ядра `rt`: интерфейсы, адреса, маршруты, `ip_forward`, правила iptables.

- `bootHost` — «загрузка»: состояние ядра собирается заново из файлов. Поэтому `reboot` стирает всё, что не записано.
- `netStart` — `systemctl restart network`: читает etcnet и пишет понятные сообщения об ошибках в конфигах.
- `send` ведёт пакет: таблица маршрутов → проверка пересылки и FORWARD → POSTROUTING (NAT) → соседи в сегменте (ARP) или GRE-инкапсуляция. `roundtrip` отправляет ответ обратно с учётом NAT по пути.

## Уровни и проверка

Уровень — объект в массиве `src/levels/<блок>.js`. Поле `build` создаёт его файлы при старте, `solve` — эталонное решение для тестов. Блок «Сеть» вместо `build` использует `setup` (сломать что-то в свежей лаборатории) и `check` (команда `labcheck`). Подробно — [ADDING_LEVELS.md](ADDING_LEVELS.md).

## Сборка в один файл

`scripts/bundle.mjs` обходит импорты от `src/main.js`, склеивает модули в том порядке, в котором их выполнил бы браузер, убирает `import`/`export` и проверяет, что имена верхнего уровня не совпадают. `tests/bundle.test.js` запускает собранный скрипт с поддельным DOM: если модуль на старте обращается к чему-то, что объявлено позже, тест упадёт.

Из-за склейки модулю нельзя на верхнем уровне использовать то, что создаётся в модуле, который импортирует его самого (циклический импорт). Внутри функций — можно.
